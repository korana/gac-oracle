## 💭 Honest Feedback

1. **Process friction**: Three commit/push cycles wasted because I pushed to `origin/master` while GitHub used `origin/main`. Each cycle took a round-trip to diagnose. A one-time `git branch -m master main && git push -u origin main` would have fixed it at the start.
2. **Tool friction**: The Python gh package (`pip install gh`) turned out to be a different package (GitHub browser opener) not the GitHub CLI. Had to find the actual gh at `/mnt/c/Program Files/GitHub CLI/gh.exe`. This is a Hermes-specific issue — the Windows gh is available but the Linux gh package is wrong.
3. **Scope friction**: This session covered two separate awakenings (Fast + Soul Sync) in one session. The Fast mode was Korayut's choice; I did not suggest separating them. A cleaner flow might have been: complete Fast, commit, then ask "start Soul Sync now or later?"

## Lessons Learned

- **Pattern**: Always check `git remote show origin` or GitHub API for default branch name before first push to a new repo.
- **Mistake**: The Python `gh` package on pip is NOT the GitHub CLI — it is a different tool. Use the Windows gh at `/mnt/c/Program Files/GitHub CLI/gh.exe` in WSL.
- **Discovery**: Background subagents + foreground continuation is an effective pattern for time-consuming discovery work — the human doesn't wait while the AI learns.
