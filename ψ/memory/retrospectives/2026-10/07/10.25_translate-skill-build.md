## 💭 Honest Feedback

1. **Process friction**: The `/learn` + `/translate` cycle was iterative — each repo added features, but two were dead ends (API-keyed). I could have asked upfront "do you have RunPod/RapidAPI keys?" before spending time building those skills. A two-question checkpoint at the start of a `/learn` session would have saved cycles.

2. **Tool inconsistency**: `execute_code` uses different Python environments across kernel sessions — some have `urllib.request.Request`, others only `urllib.request`.`urlopen`. I kept hitting `AttributeError: module 'urllib' has no attribute 'Request'` and had to import differently each time. The `from urllib.request import Request` form was reliable; the `__import__('urllib.request')` form was not.

3. **Skill description length**: The description kept failing at exactly 60 characters. I trimmed it three times before it passed. The skill index silently truncates at 60 chars, so the routing description was being cut mid-word. Better to write to 50 chars or fewer to have buffer.

## Lessons Learned

- **Pattern**: When building a skill from user-provided repos, ask about hard constraints (API keys, pip installs, platform) before investing in implementation. Dead-end first steps waste context.
- **Mistake**: Never assume a translation API preserves structural markers (punctuation, code fences, math). Always test with inputs that have mixed scripts and structural syntax.
- **Discovery**: MyMemory drops English sentence-ending punctuation (`.`) when translating to Thai — this is a known limitation of their MT engine. Thai full stop `๏` is the correct repair target for clause boundaries.
